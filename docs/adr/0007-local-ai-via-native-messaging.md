# ADR-0007: AI 는 크롬 네이티브 메시징으로 내 PC 의 claude CLI 를 부르고, 정답 판정은 하지 않는다

- 상태: 채택
- 날짜: 2026-10-29

## 배경

코드 리뷰, 힌트, CS 답변 점검에 AI 가 있으면 좋다. 하지만 API 크레딧은 쓰지 않기로 했다. 이 PC 에는 claude 가 설치돼 있고, codex 는 npx 로 쓰며, Ollama 는 없다. RTX 4060 Laptop(8GB), 램 31GB.

## 결정

- 크롬 네이티브 메시징 → 내 PC 의 작은 연결 프로그램 → `claude -p`. 연결 프로그램은 codex, agy, Ollama 로 바꿀 수 있게 부르는 명령 하나만 갈아 끼우는 구조
- 연결 프로그램은 `C:\w\` 아래에 둔다(사용자 폴더의 한글 경로에서 빌드가 깨진 적이 있다)
- 우리 확장 ID 만 부를 수 있게 매니페스트의 `allowed_origins` 로 막는다. Claude 는 도구 없이 답만 하게 부른다
- AI 가 하는 것: 코드 리뷰, 3단계 힌트(유형 → 무엇을 저장할지 → 핵심 한 줄), 접근 메모 점검, CS 답변 채점 제안
- AI 가 하지 않는 것: 정답 판정. 맞았는지는 테스트 실행과 사이트 제출로만 안다
- AI 에 보내는 것: 내 요약, 메모, 코드만. 지문은 페이지에서 긁어 보내지 않는다(ADR-0001)

## 이유

혼자 쓰는 도구라 이미 쓰는 구독 도구로 충분하다. 정답 판정을 AI 에 맡기면 틀린 "맞았다"가 복습 기록을 오염시킨다.

## 고려한 대안

- Claude API 직접 호출: 크레딧을 쓴다. 남에게 서비스로 열 때는 이 길로 바꿔야 한다
- 로컬 모델(Ollama): 설치가 필요하고, 8GB 그래픽 메모리로 코드 리뷰 품질이 충분한지 확인하지 않았다

## 결과

- 확장이 깔린 노트북에서만 AI 를 쓸 수 있다. 폰 웹에서는 AI 없이 복습만 한다
- 연결 프로그램 등록(레지스트리)은 내가 한 번 해야 한다
- AI 는 없어도 되는 보조다. 연결이 고장 나도 기록, 복습, 실행은 된다
