# ADR-0009: Next.js + Tailwind, Supabase 새 프로젝트 study-log, 깃허브 로그인은 내 계정만

- 상태: 채택 (배포 주소는 제안)
- 날짜: 2026-10-29

## 배경

폰과 노트북, 확장이 같은 기록을 봐야 해서 서버 저장이 필요하다. 혼자 쓰고 무료 안에서 돌리고 싶다.

## 결정

- 웹은 Next.js + Tailwind(포트폴리오와 같은 조합). Next.js 는 작업 전에 `node_modules/next/dist/docs/` 를 먼저 읽는다(버전이 바뀌었다)
- 홈 폴더에 떠돌이 `pnpm-workspace.yaml` 이 있어 이 저장소에 자체 워크스페이스 파일을 둔다. 웹, 확장, 공용 부품을 한 워크스페이스에
- 데이터는 Supabase 새 프로젝트 `study-log`(서울, 2026-10-29 생성). CLI 는 `npx supabase` 로 로그인돼 있다
- DB 비밀번호는 Claude 가 쓰지 않는다. 내가 정해 보관하고, 비밀번호가 필요한 단계(`link`, `db push`)는 내가 터미널에서 입력한다
- 로그인은 깃허브 아이디로. 행 수준 보안(RLS)으로 내 계정만 읽고 쓴다
- 배포는 Vercel. 주소는 `study.chanbin.dev` 제안(미확정)
- 블로그 초안은 노션 "블로그 글" DB 에 발행 끈 채로(블로그 파이프라인과 같은 길)

## 이유

이미 익숙한 조합이라 첫 버전을 빨리 낼 수 있다. Supabase 는 로그인, DB, RLS 가 한곳에 있다.

## 고려한 대안

- 하루치처럼 브라우저 저장만: 폰과 확장이 기록을 나눠 갖지 못한다
- Cloudflare Workers + D1: 하루치에서 써 봤지만 로그인과 권한을 직접 짜야 한다

## 결과

- 무료 프로젝트 두 칸(frost-log, study-log)을 다 썼다. 다른 프로젝트가 필요해지면 하나를 정리해야 한다
- 무료 프로젝트는 오래 안 쓰면 멈춘다. 매일 쓰면 문제없다
