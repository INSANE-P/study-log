# ADR-0018: 에디터가 있는 사이트에서는 그 에디터로 풀고, 패널은 메모와 타이머와 기억 신호만 맡는다

- 상태: 제안 (사용자가 바꾸자고 하면 되돌린다)
- 날짜: 2026-10-30
- 대체 예정: ADR-0002 의 "코드 복사" 흐름, ADR-0003 의 "패널 안 에디터"

## 배경

처음엔 사이드 패널 안 에디터에서 풀고 코드를 복사해 사이트에 제출하기로 했다. 사용자가 "옆 에디터에서 코딩하는 방식이 맞나, 대부분 사이트에 푸는 에디터가 있나"를 물었다. 다시 보니 패널은 최소 360px 이라 코드 쓰기에 좁고, 바로 옆 사이트에 넓은 에디터가 있으며, 결국 사이트에서 제출해야 해서 복사가 한 번 더 생긴다.

## 결정

- 프로그래머스, LeetCode 처럼 문제 화면에 에디터가 있는 사이트: 그 에디터에서 풀고 제출한다. 우리 패널은 타이머, 메모 네 칸, 이 문제의 기억 신호, 지난 기록, 힌트만 둔다. 정답 판정이 뜨면 사이트 에디터의 내 코드를 읽어 와 기록에 남긴다(백준허브 방식)
- 에디터가 없는 경우(백준, 직접 만든 프론트엔드 문제, 복습 때 다시 풀기): 웹의 넓은 우리 에디터를 쓴다. 패널에서 버튼 하나로 옆 창에 연다. 시험 모드(ADR-0004)는 여기서 쓴다

## 이유

- 좁은 패널에 에디터를 억지로 넣지 않아도 되고, 복사 단계가 없어진다
- 패널이 가벼워져 유리와 빛을 쓰기 좋다(ADR-0015)

## 고려한 대안

- 처음대로 패널 안 에디터: 시험 모드를 문제 풀 때도 쓸 수 있지만 좁고 복사가 생긴다

## 결과

- 사이트 화면 구조가 바뀌면 코드 읽기가 깨진다. 감지 규칙과 함께 사이트별 파일 하나에 모은다(ADR-0002)
- 사이트 에디터의 자동완성은 우리가 끌 수 없다. 시험처럼 연습하고 싶으면 웹 에디터로 연다
