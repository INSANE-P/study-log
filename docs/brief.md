# study-log 브리프

2026-10-30 정함. 무엇을 왜 만드는지, 잘됐는지 무엇으로 아는지 적는다. 결정 하나하나의 이유는 `docs/adr/` 에 있다.

## 한 문장

날마다 쓸 수 있는 시간이 다른 내가 수시 면접과 3월 공채 코테를 함께 준비할 수 있게, 오늘 할 것을 고민 없이 받고, 푼 것과 막힌 이유를 한곳에 남기고, 잊기 전에 다시 꺼내 보게 하는 도구. 그 기록은 블로그 글감이 된다.

쓰는 사람은 나 한 명이다. 동아리나 다른 사람에게 열지 않는다.

## 왜: 지금까지 안 이어진 이유 네 가지

2026-10-30 에 물었을 때 네 개를 다 골랐다. 하나만 고쳐서는 안 이어진다는 뜻으로 읽고, 이유마다 대응을 하나씩 둔다.

| 안 이어진 이유 | 도구가 하는 일 |
| --- | --- |
| 뭘 풀지 몰라서 | 오늘 화면이 할 것을 정해 준다. 새 문제는 고른 목록(링크)에서, 복습은 FSRS 가, CS 는 단원 순서대로 |
| 풀어도 잊어서 | 내 말로 쓴 요약과 막힌 곳으로 복습 카드를 만들고, 잊을 때쯤 다시 보여 준다 |
| 프로젝트에 밀려서 | 바쁜 날은 복습 카드 3장, 5분만 해도 "한 날"로 친다. 문제 사이트 옆 사이드 패널에서 바로 연다 |
| 기록이 흩어져서 | 프로그래머스, LeetCode, 직접 만든 문제, CS 까지 한곳에 남긴다. 사이트가 바뀌어도 기록은 내 것 |

## 수시와 공채를 같이 가는 방식

2026-10 에 지원한 프론트엔드 수시 공고 네 곳의 전형을 보면 코딩테스트 단계가 없고 과제와 면접이 많다. 3월 공채는 코테가 먼저 온다. 그래서 날마다 둘 다 조금씩 하되 시기에 따라 무게를 옮긴다(ADR-0010).

| 시기 | 무게 |
| --- | --- |
| 2026-11 ~ 12 | CS 면접 쪽이 더 크다. 코테는 유형을 넓게 한 바퀴 |
| 2027-01 ~ 공채 | 코테 쪽이 더 크다. CS 는 복습 카드 위주 |

주 언어는 파이썬, 보조는 자바스크립트(프론트엔드 구현 문제와 JS 로만 보는 시험).

## 측정값 Y

실제로 쓰기 시작한 월요일부터 4주가 끝나면 아래 두 값을 잰다. 브랜드와 디자인을 먼저 하기로 해서(`docs/pipeline.md`) 시작일은 구현이 끝나는 날에 맞춰 정한다. 목표는 2026-11-09(월) 시작, 12-06(일) 끝. 둘 다 넘으면 "쓸 만하다"로 본다.

| | 무엇 | 기준 | 재는 곳 |
| --- | --- | --- | --- |
| Y1 이어짐 | 4주 중 "한 날"이 4일 이상인 주 | 4주 중 3주 이상 | 기록 테이블의 날짜 |
| Y2 남음 | 4주 동안 복습한 코테 문제 중 "혼자 풂" 비율 | 70% 이상, 복습 10번 이상일 때만 판단 | 복습 기록의 결과 |

- **한 날**: 복습 카드 3장 이상, 또는 문제 하나 기록, 또는 CS 단원 하나를 끝낸 날
- **혼자 풂**: 복습(카드로 떠올리기와 다시 풀기 모두) 때 힌트 없이 접근을 떠올렸거나 풀어낸 경우. 힌트를 봤거나 못 하면 "혼자 풂"이 아니다
- 기준값이 없다. 지금까지 기록이 흩어져 있어 비교할 숫자가 없으므로, 첫 주 값이 기준이 된다
- 같이 보는 것(판단에는 안 씀): 4주 동안 나온 블로그 초안 수, CS 예상 질문 중 3분 안에 내 말로 답한 수

## 하지 않을 것

- 문제 지문, 예제, 그림, 공식 해설 저장. 링크, 번호, 제목, 내 요약만 남긴다(ADR-0001)
- 사이트에 대신 제출하기. 제출은 내가 직접 누른다(ADR-0002)
- AI 가 정답을 판정하기, AI 코드 자동완성(ADR-0004, ADR-0007)
- API 크레딧 쓰기. AI 는 내 PC 의 터미널 도구로만(ADR-0007)
- 다른 사람에게 서비스로 열기, 랭킹, 공유
- 강의나 커리큘럼을 새로 사기. 문제는 공개된 링크 목록에서 고른다
- 첫 버전에서 백준 감지. 서비스 상태가 확인되지 않았다(`docs/research/2026-10-29-similar-services.md`)

## 하루 사용 장면

오늘 화면은 "오늘 몇 분 있어요?"에 맞춰 할 것을 세 크기로 내놓는다(ADR-0010).

**바쁜 날, 5분.** 지하철에서 폰으로 오늘 화면을 연다. 복습 카드 3장이 나온다. 카드 앞면은 내가 쓴 요약("구간 합을 빠르게 → 누적합")이고, 접근과 막힌 곳을 떠올려 본 뒤 뒤집어 결과(혼자 떠올림 / 힌트 보고 떠올림 / 못 떠올림)를 고른다. 화면 문구는 아직 정하지 않았다. 끝나면 그날은 한 날이다.

**보통 날, 30분 ~ 1시간.** 노트북에서 프로그래머스 문제를 연다. 오른쪽 사이드 패널이 문제 번호를 알아보고 전에 푼 기록을 불러온다. 접근을 두 줄 쓰고, 파이썬으로 풀다 막히면 막힌 곳 칸에 적는다(그 순간 타이머 시간이 찍힌다). 코드를 복사해 사이트에 내가 제출한다. "맞았습니다"가 뜨면 기록이 저장되고, 요약 한 줄을 쓰면 복습 카드가 생긴다. 남은 시간에 CS 카드 3장.

**여유 있는 날, 1시간 이상.** 위에 더해 CS 단원 하나(15분: 질문, 설명, 개발자 도구로 직접 확인, 내 프로젝트와 잇기, 내 말로 설명). 원하면 로컬 Claude 에게 코드 리뷰나 내 설명의 빈 곳을 묻는다.

**일요일.** 그 주 기록으로 블로그 초안 재료가 모인다. 글로 만들지는 내가 정한다.

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 도구 만들기가 공부를 대신한다 | 첫 화면이 돌아가면 그날 바로 문제 하나를 풀어 기록한다. 4주 뒤 Y 로 판단하고, 그 전엔 기능을 늘리기보다 쓰면서 불편한 것만 고친다 |
| 기록할 게 많아 귀찮아진다 (노션 기록장이 실패한 이유) | 꼭 넣을 건 결과 하나. 메모 네 칸은 다 비워도 저장된다. "맞았습니다"는 자동으로 기록한다 |
| 프로젝트와 지원 일정에 또 밀린다 | 5분짜리 최소 단위. 끊긴 날을 탓하는 표시를 두지 않는다(ADR-0011) |
| 사이트 화면이 바뀌어 확장 감지가 깨진다 (백준허브의 2026-03 프로그래머스 업로드 고장) | 감지는 편의 기능이다. 패널에 "맞았어요" 직접 기록 버튼을 늘 둔다 |
| 약관 문제 | 지문을 가져오지 않고, 대신 제출하지 않는다(ADR-0001, 0002) |
| 로컬 AI 연결이 고장 나거나 한도가 찬다 | AI 는 없어도 되는 보조다. 기록, 복습, 실행은 AI 없이 모두 된다 |
| CS 내용이 틀린다 | 단원마다 MDN, web.dev 같은 공식 문서 근거를 달고, 대조 전엔 "확인 전"으로 표시한다 |
| 브랜드와 화면 다듬기에 시간이 쏠린다 | 브랜드는 정해진 단계 하나로 묶고(`docs/pipeline.md` 3단계), 그동안 화면 없는 부품을 먼저 만든다 |
