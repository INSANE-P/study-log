# 디자인 심사 기준

컨셉 후보, 캐릭터 시안, 화면 시안, 모션을 판정할 때 쓰는 기준이다. Codex 와 제미나이가 그림 파일을 직접 읽고 따로 판정하며, 컨셉 단계는 서로 못 보는 심사 에이전트 다섯이 채점한다(`docs/pipeline.md` 3-2, 3-6).

## AI 티를 줄이는 원칙

방향 없이 만들면 학습 데이터에서 가장 흔한 꼴로 모인다. 그래서 형용사 대신 실제 사물과 구체 제약에서 출발한다.

1. **도메인의 실제 사물과 표기를 가져온다.** 오답노트, 연습장, 채점 동그라미와 빗금, 형광펜, 책갈피, 플래시카드, 초시계
2. **큰 숫자 점수를 앞세우지 않는다.** 혼자 푼 비율 같은 숫자는 계산 결과다. 화면은 공부한 흔적으로 보여 준다
3. **카드 하나에 다 담지 않는다.** 틀 자체가 사물(카드, 노트 한 장, 시험지)이 되게 한다
4. **글꼴에 역할을 준다.** 읽는 글, 코드, 손글씨 느낌의 표시를 나누고 장식용 글꼴은 쓰지 않는다
5. **색은 뜻이 있을 때만.** 빛나는 효과, 그라데이션 글자는 쓰지 않는다
6. 바탕은 순수한 검정과 흰색이 아니라 색이 살짝 섞인 검정과 흰색

피할 꼴: 큰 숫자와 작은 단위를 나란히 둔 지표 카드, 모든 곳의 둥근 사각형과 흐린 그림자, 카드 속 카드, 알약 배지 남발, 어두운 바탕의 빛나는 강조색, 같은 간격 목록 반복, 다 가운데 정렬.

## 이 도메인의 기준

- **공부를 방해하지 않는다.** 문제를 푸는 동안 패널은 조용하다. 움직임과 알림은 기록하는 순간, 카드를 뒤집는 순간에만
- **끊긴 날을 탓하지 않는다.** 빈 날이 벌처럼 보이는 모양, "연속 며칠째", 빨간 경고는 쓰지 않는다(ADR-0011)
- **좁은 폭에서 산다.** 사이드 패널 약 360px 에서 에디터와 메모 네 칸이 무너지지 않는다
- **5분 장면이 폰에서 된다.** 엄지로 카드를 넘기고 결과를 고를 수 있다
- **코드가 주인공일 때는 코드가 잘 읽힌다.** 고정폭 글꼴, 충분한 대비, 문법 색이 브랜드 색과 부딪히지 않는다

## 모션 기준

- 움직임이 뜻을 가진다(카드를 뒤집는다 = 답을 확인한다, 동그라미가 그려진다 = 혼자 풀었다). 꾸밈용 반짝임, 떠다니는 파티클 금지
- 개별 움직임 300ms 안팎, 화면 전체 연출 1초 이하, 표준 감속 곡선. 튀는 탄성 곡선 금지
- 반복 재생 없음. `prefers-reduced-motion` 이면 움직임 없이 바로 결과
- 반투명으로 서서히 나타나게 하기보다 제자리로 이동해 들어온다(불투명한 그림 문법과 맞춘다)

## 판정 항목

| 코드 | 항목 | 걸리는 경우 |
| --- | --- | --- |
| S | AI 티 | 위의 피할 꼴 |
| D | 도메인 진정성 | 공부 도구라는 게, 코테와 CS 라는 게 그림에서 안 드러남 |
| G | 한눈에 읽힘 | 2초 안에 오늘 무엇을 할지 모름, 한 화면 요소가 너무 많음 |
| B | 탓하지 않음 | 빈 날, 밀린 복습이 벌처럼 보임 |
| C | 대비와 테마 | 글자 대비 4.5 대 1 미만, 밝게와 어둡게 한쪽에서만 성립 |
| W | 폭 | 360px 패널이나 폰 폭에서 무너질 구조 |
| K | 코드 가독성 | 에디터 글꼴, 대비, 문법 색이 브랜드와 부딪힘 |
| I | 기억에 남음 | 3초 보고 떠오르는 장면이 없음, 포폴 첫 장면이 안 됨 |
| M | 모션 | 위 모션 기준 위반 |

판정은 걸린 곳마다 코드, 이유, 고칠 방향 한 줄. 문제가 없으면 적지 않는다. 마지막에 시안 순위와 이유.

## 컨셉 채점 (3-2)

심사 에이전트 다섯이 후보마다 1~5점으로 매긴다. 합은 25점.

| 항목 | 묻는 것 |
| --- | --- |
| 이어짐 | 바쁜 주가 지나도 다시 열고 싶어지나 |
| 도메인 | 코테와 CS 공부라는 게 바로 보이나 |
| 차별 | 비슷한 학습 앱, 기록 템플릿과 달라 보이나 |
| 움직임 | 뜻 있는 모션이 자연스럽게 나오나 |
| 오래 감 | 몇 달 써도 유치하거나 질리지 않나 |
