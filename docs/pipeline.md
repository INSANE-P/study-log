# 개발 파이프라인

study-log 를 어떤 순서로, 누가 무엇을 맡아 만드는지 적는다. 단계마다 결과물이 남는 자리가 정해져 있고, 다음 단계는 그 파일을 읽고 시작한다. 대화창에만 있는 결과는 없는 것으로 친다.

2026-10-30 사용자 결정: **브랜드와 디자인을 먼저 하고, 그 위에 구현한다.** 세련되고 움직임이 있고 캐릭터가 있는, 이 도메인에 맞는 모양을 원한다.

## 맡는 쪽

| 맡는 쪽 | 하는 일 |
| --- | --- |
| Claude Code | 조사 검증, 후보 만들기, 디자인 파일 작업, 코드, 문서, 다른 도구 결과의 검사 |
| Codex | 화면 문구 다듬기와 검토, 디자인 독립 심사 |
| 제미나이(`agy`) | 캐릭터와 브랜드 시안 그림, 디자인 교차 심사, 그림 판독 |
| 나 | 고르기, 방향 정하기, dev 서버를 띄워 화면 확인, DB 비밀번호 입력 |

## 3. 브랜드와 디자인

구현 전에 끝낸다. 순서대로 가고, 각 단계의 고르기는 내가 한다.

### 3-1. 도메인과 참고 조사

- 공부하는 사람이 실제로 쓰는 사물과 표기를 모은다. 후보: 오답노트, 연습장 모눈, 채점 동그라미와 빗금, 형광펜, 책갈피, 플래시카드, 초시계, 시험지 여백의 풀이, 단어장 고리
- 참고 서비스 화면: Anki, LeetSRS, 백준허브, 프로그래머스 에디터, 시험장 에디터, 국내 학습 앱
- UI 와 학습 연구: NN/g, 크롬 사이드 패널 가이드, 간격 반복과 떠올리기 연구, 동기와 끊김 연구
- 남는 자리: `docs/research/`

### 3-2. 컨셉 후보와 채점

- 서로 다른 방향의 컨셉 후보를 여러 개 만든다(성격, 중심 사물, 캐릭터 한 줄, 움직임 한 줄)
- 서로의 답을 못 보는 심사 에이전트 다섯이 각자 채점한다. 심사위원: 나 같은 사용자(바쁜 취준생), 학습과학 연구자, 프론트엔드 면접관(포폴로 볼 때), 브랜드 디자이너, 모션 디자이너. 항목은 `docs/design-judge.md`
- 점수가 높은 둘셋을 내가 고른다. 고른 이유는 ADR

### 3-3. 이름, 색, 글꼴

- 이름 후보와 색, 글꼴을 컨셉에서 끌어낸다. `study-log` 는 작업 이름이다
- 남는 자리: `docs/brand.md`

### 3-4. 캐릭터

- `gemini-image` 스킬 흐름: `agy` 로 2x2 그리드 시안 → Claude 가 먼저 거르고 보여 줌 → 내가 고름 → 기준 시트 한 장 → 자세별 자산 → 투명 PNG 와 SVG
- 남는 자리: `public/brand/`, 프롬프트와 모델은 `docs/assets.md`

### 3-5. 화풍 규칙

- 그림과 화면이 한 결이 되게, 캐릭터의 선 굵기, 모서리, 색, 그림자 방식을 화면 부품이 같이 쓴다
- 남는 자리: `docs/design-system.md` (색과 간격 토큰 포함)

### 3-6. 화면 시안과 심사

- 디자인 파일에 주요 화면을 그린다: 오늘(세 크기), 사이드 패널(에디터와 메모 네 칸, 약 360px 폭), 복습 카드, 기록 모아 보기(ADR-0011), 폰 폭의 5분 복습
- 판마다 캡처를 남기고 Codex 와 제미나이가 같은 기준으로 따로 판정한다. 둘 다 짚은 곳부터 고친다
- 걸린 곳만 고쳐 다시 심사하고, 내가 확정한다

### 3-7. 모션

- 움직임에는 뜻이 있다(예: 카드를 뒤집는다, 채점 동그라미가 그려진다). 꾸밈용 반짝임과 떠다니는 파티클은 없다
- 개별 움직임 300ms 안팎, 감속 곡선, 튀는 탄성 곡선 금지, `prefers-reduced-motion` 을 따른다
- 디자인 파일에서 키프레임을 넣고 영상으로 뽑아 프레임을 확인한 뒤 심사한다

### 3-8. 화면 문구

- 처음엔 Claude 가 사실에 맞게 쓴다. 화면에 넣기 전에 모두 Codex 검토를 거치고, 검토 뒤 고치면 다시 거친다(다이얼로그, 버튼, aria-label 까지)
- 말투와 고른 이유는 `docs/writing.md`

## 4. 구현

- 이슈 → 브랜치 → PR → 머지
- 브랜치: `<type>/#<이슈번호>-<짧은-영문-설명>`
- 커밋: `type: 한 문장 (#이슈번호)`, 한 커밋에 목적 하나. type 은 `feat` `fix` `refactor` `style` `design` `copy` `docs` `chore` `test`
- 커밋과 PR 에 AI 서명(Co-Authored-By, 생성 도구 푸터)을 넣지 않는다
- dev 서버는 내가 띄운다. Claude 는 띄우지 않는다
- 화면이 바뀌는 작업은 내가 로컬에서 확인한 뒤 한 번에 커밋하고 푸시한다
- 화면 없는 부품(FSRS 계산, 오늘 고르기, 실행기, 감지 규칙)은 순수 함수로 두고 시험을 붙인다
- DB 비밀번호는 Claude 가 쓰지 않는다. `supabase link`, `db push` 는 내가 터미널에서 입력한다
- 공개 저장소다. 키, 토큰, 지원한 회사와 개인 정보는 넣지 않는다
