- **확인함**: 2026-10-30 에 원문(논문 초록이나 본문, 공식 문서, 회사 공식 블로그, 공식 소스 코드)을 직접 열어 본 것

- **관행**: 연구가 아니라 사람들이 실제로 쓰는 방식. 학생 기고나 양식 배포 글처럼 2차 자료가 원래 출처다. 숫자를 근거로 쓰지 않는다

- 모든 출처의 확인 날짜는 2026-10-30 이다

## 1. 공부 도메인의 실제 사물과 표기

### 1-1. 오답노트

- **관행 (원문 열어 봄)**: 대학생 선배 기고(한경 생글생글, 2023-09-25). 틀린 문제와 풀이를 적고 옆에 분류와 핵심 포인트를 짧게 메모한다
  - 틀린 이유를 "단순 실수 / 중간까지는 풀었음 / 접근법을 모름" 세 갈래로 나눈다. 나눠 두면 복습할 때 필요한 유형만 고를 수 있다
  - 다시 풀 때 풀이를 포스트잇으로 가리고 힌트 없이 푼다
  - 요일을 정해 주 2회쯤 복습하고, 쌓이면 부담이 되니 자투리 시간을 쓴다
  - 출처: https://sgsg.hankyung.com/article/2023092295721
- **확인 전**: 문제, 분석, 개념 정리로 칸을 나누는 방식(dhnews), 다시 풀어 맞아도 틀린 문제로 남기고 원인을 적는 방식(riroschool), 아래 풀이를 연습장으로 가리고 다시 푸는 방식(내일신문 2019). 검색 요약으로만 봤다
- **화면 아이디어**
  - 메모 네 칸(요약, 접근, 막힌 곳, 언어 메모)이 오답노트 칸과 거의 같다. 틀을 "오답노트 한 장"으로 그리면 사물이 곧 화면이 된다
  - "막힌 곳"에 세 갈래 분류(실수 / 중간까지 / 접근 모름)를 붙이면 복습 고르기의 재료가 된다
  - 포스트잇으로 풀이 가리기 = 복습 카드 뒷면을 덮은 종이. 뒤집기보다 "가린 종이를 떼는" 움직임도 후보

### 1-2. 채점 표기 (동그라미, 빗금, 세모)

- **확인함**: W3C 국제화 메일링 리스트(2021-01-14, Fuqiao Xue). 아이콘 검토 문서의 "동아시아에서는 체크가 틀림, 동그라미가 맞음"이라는 문장을 "일본, 한국 같은 일부 나라"로 좁히자는 의견이다. 중국에서는 체크가 맞음이라서다. 즉 한국에서 체크(✓)는 틀림으로 읽힐 수 있다
  - 출처: https://lists.w3.org/Archives/Public/public-i18n-archive/2021JanMar/0033.html
- **확인함**: 영어 위키백과 Check mark 문서는 일본만 적고 한국은 언급하지 않는다(W3C 국제화 페이지를 각주로 듦). 한국어 위키백과 "체크 표시"는 O 표시가 한국에서도 쓰인다고만 적고 채점 방식은 설명하지 않는다
  - 출처: https://en.wikipedia.org/wiki/Check_mark , https://ko.wikipedia.org/wiki/체크_표시
- **관행 (원문 열어 봄)**: 스터디 플래너 양식 글(육아크루, 2026-10-10)은 할 일에 ○(다 함), △(하다 멈춤), ×(못 함)를 쓰고, △와 ×는 다음 날 맨 위 줄로 옮긴다
  - 출처: https://www.yugacrew.com/crewletter/study-planner-printable
- **확인 전**: 한국 시험지 채점에서 틀린 문항에 빗금(/)을 긋는 관행. 널리 알려진 관행이지만 이를 적은 원문 자료는 찾지 못했다
- **화면 아이디어**
  - "혼자 풂" = 빨간 펜 동그라미가 그려진다. "힌트 보고 풂" = 세모. "못 풂" = 빗금이 아니라 "다시 볼 표시"로 바꾼다(탓하지 않음)
  - 체크(✓)를 "완료" 표시로 쓰면 한국 사용자에게 "틀림"으로 읽힐 수 있다. 완료 표시는 동그라미 쪽이 도메인에 맞다
  - △를 다음 날 맨 위로 옮기는 플래너 규칙 = 못 끝낸 것은 벌이 아니라 "내일 첫 줄"이 된다

### 1-3. 형광펜

- **관행 (출처 없음, 관찰)**: 교과서와 개념서에서 핵심어에 긋는다. 색을 뜻별로 나누는 사람이 많다
- **화면 아이디어**: 요약 한 줄의 핵심어에만 형광펜 바탕. 화면 전체 강조색 대신 "내가 그은 곳"만 색이 있다. 형광펜이 왼쪽에서 오른쪽으로 그어지는 움직임은 "핵심을 골랐다"는 뜻

### 1-4. 플래시카드와 단어장 고리

- **관행 (출처 없음, 관찰)**: 구멍 뚫린 카드 묶음을 링으로 꿰어 넘긴다. 외운 카드는 빼고, 못 외운 카드는 남긴다
- **화면 아이디어**: 오늘 복습 3장 = 링에 걸린 카드 세 장. 넘기면 링을 따라 뒤로 돈다. 다 넘기면 링이 닫힌다(그날은 "한 날"). 링에 걸린 장 수가 곧 남은 양이라 숫자 배지가 필요 없다

### 1-5. 연습장 모눈

- **관행 (출처 없음, 관찰)**: 수학 풀이와 코딩 손풀이에 모눈이나 줄 연습장을 쓴다
- **화면 아이디어**: 에디터 옆 "접근" 칸 바탕에만 옅은 모눈. 생각을 적는 자리와 정리된 기록을 구분한다
- **주의**: impeccable 목록은 뜻 없는 장식용 격자 바탕을 AI 티로 꼽는다(6절). 모눈은 "손으로 풀어 보는 자리"에만 둔다

### 1-6. 초시계

- **관행 (출처 없음, 관찰)**: 시험 대비로 문제당 시간을 재며 푼다. 열품타 같은 앱이 과목별 스톱워치를 쓴다(2절)
- **화면 아이디어**: 막힌 곳을 적는 순간 타이머 시간이 찍힌다(브리프의 보통 날 장면). 초시계의 "랩" 버튼과 같은 뜻. 오늘 크기 5분/30분/1시간은 초시계 눈금 세 개로 그릴 수 있다

### 1-7. 인덱스 탭

- **관행 (출처 없음, 관찰)**: 개념서와 문제집 옆면에 단원별 색 탭을 붙인다
- **화면 아이디어**: 360px 패널 위쪽 탭(코테 / CS, 또는 요약 / 접근 / 막힌 곳 / 언어 메모)을 종이 옆면 탭처럼. 좁은 폭에서 메모 네 칸을 한 번에 펼치지 않고 탭으로 넘길 수 있다

### 1-8. 스터디 플래너 10분 타임테이블

- **관행 (원문 열어 봄)**: 위 육아크루 양식 글. 가로 한 줄이 한 시간, 한 칸이 10분(한 시간 여섯 칸). 과목마다 색을 정하고 공부를 마칠 때마다 그만큼 칸을 칠한다. 하루가 끝나면 색별 칸 수를 세어 과목별 시간을 적는다
- **화면 아이디어**
  - 기록 모아 보기(ADR-0011)를 10분 칸 색칠로. 칠한 칸만 보이고 비어 있는 칸은 그냥 종이라서 벌처럼 보이지 않는다
  - 코테 색, CS 색 두 가지만. 5분 날은 한 칸 반쯤, 그래도 칠해진다

## 2. 참고 서비스 화면

### 2-1. Anki

- **확인함 (공식 매뉴얼)**
  - 카드는 처음에 질문만 보이고, Show Answer 나 Space 로 답을 연다
  - 버튼 넷의 뜻: Again 은 틀렸거나 못 떠올림, Hard 는 맞았지만 의심했거나 오래 걸림, Good 은 맞았고 약간 애씀, Easy 는 애쓰지 않고 떠올림
  - 각 버튼에 그 버튼을 누르면 다음에 언제 다시 보는지가 표시된다
  - 단축키: 1 Again, 2 Hard, 3 Good(Space, Enter 도), 4 Easy
  - 반쯤 맞으면 스스로에게 엄격하라고 하고, 버튼 넷이 어려우면 Again 과 Good 둘만 써도 된다고 적는다
  - 환경설정에 "다음 복습 시간을 버튼 위에 표시"와 "남은 카드 수 표시"를 끄는 옵션이 있다
  - 출처: https://docs.ankiweb.net/studying.html , https://docs.ankiweb.net/preferences.html
- **좋은 점**: 떠올리기 먼저, 답은 나중. 버튼마다 다음 간격이 보여 선택의 결과를 안다. 키보드로 다 된다
- **피할 점**: 버튼 넷은 결정 부담이 크다(매뉴얼도 둘만 써도 된다고 함). 남은 카드 수가 쌓이면 부담이 된다(그래서 숨기는 옵션이 있다)
- **우리에게**: 결과 셋(혼자 떠올림 / 힌트 보고 / 못 떠올림)은 Anki 의 "둘만 쓰기"와 넷 사이. ts-fsrs 등급과 어떻게 잇는지는 구현 단계 ADR 로 남긴다. 간격 표시는 "다음에 언제" 한 줄로, 숫자 일수보다 "다음 주 화요일"처럼

### 2-2. LeetSRS

- **확인함 (GitHub README)**
  - LeetCode 문제에 간격 반복을 붙이는 크롬, 파이어폭스 확장. FSRS(TS-FSRS) 사용, MIT
  - "맞았습니다" 뒤 문제 페이지에서 LeetSRS 패널이 열리고 Again/Hard/Good/Easy(1~4)를 고른다. 각 등급 옆에 언제 돌아오는지 보인다
  - 화면은 Home(오늘 볼 문제를 한 번에 하나씩)과 Calendar(앞으로 4주 복습)
  - 로드맵(Blind 75, NeetCode 150/250, Grind 75)으로 다음 문제를 제안, 새 문제 하루 한도, 문제별 일시 정지
  - 데이터는 기본 로컬, 선택적으로 내 GitHub Gist 동기화. 스트릭 추적이 있다
  - README 는 패널이 팝업인지 사이드 패널인지 밝히지 않는다
  - 출처: https://github.com/mattcdrake/LeetSRS
- **확인 전**: 크롬 웹스토어 0.4.0(2026-02-28)은 서드파티 목록(chromeboard)에서만 봤다
- **좋은 점**: "맞았습니다" 순간에 기록을 받는다. 한 번에 하나씩. 4주 달력
- **피할 점**: LeetCode 전용, 메모 칸(막힌 이유)이 핵심이 아니다. 스트릭 추적은 우리 ADR-0011 과 반대

### 2-3. NeetCode

- **확인 전**: 무료는 로드맵 진행 표시, Pro(연 $119, 평생 $219)에 간격 반복 알림이 있다는 리뷰(lodely, 2026-03)
- **좋은 점 (관찰로 알려진 것, 확인 전)**: 주제별 로드맵 나무 그림이 "무엇을 풀지"를 정해 준다
- **우리에게**: 오늘 화면이 할 것을 정해 주는 역할과 같다. 다만 진행 막대와 퍼센트는 "큰 숫자 앞세우기"가 되기 쉽다

### 2-4. 백준허브

- **확인함 (GitHub README)**: 백준, 프로그래머스, SWEA, goormlevel 에서 채점 뒤 정답을 감지해 코드를 GitHub 에 올린다(SWEA 는 업로드 버튼). 제목, 번호, 링크, 레벨, 문제 설명, 언어, 메모리, 시간 같은 메타데이터를 함께 올린다. 업로드 중 페이지를 떠나지 말라고 안내한다
  - 출처: https://github.com/BaekjoonHub/BaekjoonHub
- **좋은 점**: 정답 감지 후 자동. 기록이 내 저장소에 남는다
- **피할 점**: 문제 설명까지 올린다(우리는 ADR-0001 로 안 함). 막힌 이유는 남지 않는다. 사이트가 바뀌면 감지가 깨진다(2026-03 프로그래머스 고장, 전 조사)

### 2-5. 프로그래머스 코딩 화면

- **확인함 (문제 페이지 본문 텍스트)**: 경로(코딩테스트 연습 > 유형 > 제목), 도움말, 컴파일 옵션, 에디터 키 바인딩 선택(sublime / vim / emacs), 언어 탭(C++, Java, JavaScript, Python3 등), 문제 설명 영역, 에디터(solution 파일 탭과 시작 코드), "실행 결과" 영역과 "실행 중지", 질문하기 버튼
  - 출처: https://school.programmers.co.kr/learn/courses/30/lessons/42576
- **확인 못 함**: 영역의 좌우 배치, 코드 실행과 제출 버튼 문구는 이번에 읽은 텍스트에 없었다. 화면을 직접 캡처해 확인해야 한다
- **우리에게**: 사이드 패널이 이 화면 오른쪽에 붙는다. 사이트 자체가 이미 에디터와 결과 창으로 꽉 차 있으니 패널은 더 조용해야 한다. 사이트의 문법 색과 우리 패널 에디터 색이 나란히 보인다(판정 항목 K)

### 2-6. solved.ac 티어와 잔디

- **확인함 (공식 도움말)**: 티어는 AC 레이팅으로 정한다. 브론즈 30~150, 실버 200~650, 골드 800~1400, 플래티넘 1600~2100, 다이아몬드 2200~2600, 루비 2700~2950, 마스터 3000. 레이팅 = 가장 어려운 100문제 난이도 합 + CLASS 보너스(25~250) + 푼 문제 수 보너스(최대 200) + 기여 보너스(최대 25)
  - 출처: https://help.solved.ac/en/stats/ac-rating
- **확인 전**: 스트릭(잔디) 하루 기준 시각, 코인샵의 스트릭 프리즈(최대 2개 보유). 검색 요약으로만 봤다
- **좋은 점**: 티어 색과 보석 이름이 한국 코테 준비생에게 익숙한 언어다
- **피할 점**: 티어와 레이팅은 남과 견주는 점수다(우리는 랭킹, 공유 안 함). 잔디는 빈 칸이 끊김으로 보인다. 우리는 잔디 대신 칠한 칸만 보이는 방식(1-8)이 맞다

## 3. 크롬 사이드 패널

- **확인함 (공식 API 문서)**
  - 권한 `"sidePanel"`, 매니페스트 `"side_panel": { "default_path": ... }`. Chrome 114 부터
  - `setPanelBehavior({ openPanelOnActionClick: true })` 로 툴바 아이콘 클릭 때 패널을 여닫는다. 기본값은 false
  - `setOptions` 에 `tabId` 를 주면 그 탭에만 적용. 특정 사이트에서만 패널을 켤 수 있다
  - `open()` 은 Chrome 116 부터, 사용자 동작(아이콘 클릭, 단축키, 컨텍스트 메뉴, 확장 페이지나 콘텐츠 스크립트의 사용자 제스처)에 응답할 때만 부를 수 있다
  - `close()` 는 Chrome 141 부터. `getLayout()`(Chrome 140 부터)은 패널이 왼쪽인지 오른쪽인지 알려 준다. 위치는 사용자가 크롬 설정에서 고른다
  - API 문서에 폭을 정하는 속성이나 메서드가 없다
  - 출처: https://developer.chrome.com/docs/extensions/reference/api/sidePanel
- **확인함 (Chromium 소스, main 브랜치)**: `SidePanelEntry::kSidePanelDefaultContentWidth = 360`, 주석은 "기본이자 최소 허용 콘텐츠 폭". 사용자가 손으로 폭을 바꾸면 그 값(`prefs::kSidePanelIdToWidth`)을 쓴다. 패널 테두리 두께(8 + 구분선)가 콘텐츠 폭에 더해진다
  - 출처: https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/ui/side_panel/side_panel_entry.h , https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/ui/views/side_panel/side_panel.cc
  - 뜻: 360px 은 "약 360"이 아니라 **최소값**이다. 더 좁아지지 않고, 사용자가 넓힐 수 있다. 화면은 360 에서 성립하고 넓어지면 늘어나게 짠다
- **확인함 (공식 블로그, Oliver Dunk, Amy Steam, 2023-05-30 갱신)**: 사이드 패널은 보고 있는 페이지 옆에 계속 열려 있는 UI. 확장의 나머지 기능과 바로 이어지는 일을 할 것(단일 목적 정책이 패널에도 적용), 관련 없을 때는 보이지 않게 사이트를 제한할 것, 로고와 색, 아이콘, 글꼴이 확장과 맞을 것, 불필요한 방해 요소를 두지 말 것, 처음 쓰는 사람에게 쓰는 법을 알려 줄 것
  - 출처: https://developer.chrome.com/blog/extension-side-panel-launch
- **확인함 (공식 문서)**: "Create a side panel" 과 확장 UI 개요 페이지에는 UX 권장이나 폭 이야기가 없다. 패널은 탭 하나나 창 전체에 붙을 수 있고, 설정하면 탭을 옮겨도 열려 있다
  - 출처: https://developer.chrome.com/docs/extensions/develop/ui/create-a-side-panel , https://developer.chrome.com/docs/extensions/develop/ui
- **확인 못 함**: 공식 "side panel use cases" 페이지(개요 페이지가 링크하지만 추정한 주소는 404). 일부 2차 글의 "최소 320px" 주장은 Chromium 소스와 다르다
- **화면 규칙 후보**: 360 최소 폭 기준, 사용자 동작 없이 패널을 열 수 없으니 "맞았습니다" 감지 때도 패널을 강제로 열지 않고 아이콘 배지나 이미 열린 패널 안에서만 반응. 프로그래머스, LeetCode 에서만 켜기

## 5. 모션과 UI 가이드

### 5-1. Material 3 길이와 곡선

- **확인함 (Google 의 Material Components Android 공식 문서, M3 토큰 구현)**
  - 길이 토큰 16개: Short 50/100/150/200, Medium 250/300/350/400, Long 450/500/550/600, ExtraLong 700/800/900/1000 (ms). 움직이는 면적과 거리가 클수록 길게
  - 곡선: Standard `cubic-bezier(0.2, 0, 0, 1)`(화면 안에서 시작해 끝나는 실용 동작), Standard decelerate `(0, 0, 0, 1)`(들어올 때), Standard accelerate `(0.3, 0, 1, 1)`(나갈 때), Emphasized decelerate `(0.05, 0.7, 0.1, 1)`, Emphasized accelerate `(0.3, 0, 0.8, 0.15)`, Emphasized 는 두 구간 경로
  - 출처: https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md
- **확인 못 함**: m3.material.io 의 easing-and-duration 페이지는 자바스크립트로 그려져 본문을 읽지 못했다
- **확인 전**: M3 Expressive 의 스프링 모션 토큰(spatial, effects 와 강성, 감쇠 값)은 서드파티 플러터 라이브러리에서만 봤다. 우리 기준(튀는 탄성 금지)과 부딪힐 수 있으니 쓰기 전에 원문 확인

### 5-2. Apple HIG 모션

- **확인함 (HIG Motion, 변경 기록 마지막 2025-09-09)**
  - 목적이 있을 때만 넣고, 움직임을 위한 움직임은 넣지 않는다. 과한 애니메이션은 산만하고 몸이 불편할 수 있다
  - 움직임을 선택 사항으로. 중요한 정보를 움직임으로만 전하지 않는다
  - 피드백 움직임은 짧고 정확하게. 자주 일어나는 상호작용에는 움직임을 넣지 않는다
  - 사람이 움직임을 끊을 수 있게. 애니메이션이 끝날 때까지 기다리게 하지 않는다
  - 0.2Hz 근처로 계속 흔들리는 물체를 피한다(visionOS 절)
  - 출처: https://developer.apple.com/design/human-interface-guidelines/motion

### 5-3. NN/g

- **확인함 (Page Laubheimer, 2020-02-09, "Executing UX Animations: Duration and Motion Characteristics")**: 대부분 100~500ms. 체크박스, 토글 같은 단순 피드백은 약 100ms, 모달처럼 큰 화면 변화는 200~300ms, 큰 화면을 가로지르는 움직임만 400ms 까지. 들어올 때가 나갈 때보다 조금 길다(예: 300ms 로 나타나고 200~250ms 로 사라짐). 자주 보는 애니메이션일수록 짧고 은은하게. 너무 짧은 것보다 너무 긴 경우가 훨씬 흔하다
  - 출처: https://www.nngroup.com/articles/animation-duration/
- **확인함 (Page Laubheimer, 2020-01-12, "The Role of Animation and Motion in UX")**: 쓰임은 피드백, 동작 미리보기, 상태 변화 알림, 공간 은유와 이동 방향, 방향 잃음 막기, 조작 방법 알려 주기, 주의 끌기. 기다리는 시간을 채우는 꾸밈 애니메이션이 사용성 테스트에서 자주 짜증을 낳는다. 주의를 빼앗거나 잃을까 두렵게 만드는 데 쓰면 다크 패턴이다
  - 출처: https://www.nngroup.com/articles/animation-purpose-ux/

### 5-4. prefers-reduced-motion

- **확인함 (MDN)**: 기기에서 꼭 필요하지 않은 움직임을 줄이는 설정을 켰는지 알려 준다. 값은 `no-preference`, `reduce`. Windows 11 은 설정 > 접근성 > 시각 효과 > 애니메이션 효과, macOS Tahoe 부터 접근성 > 동작 > 동작 줄이기(그 전은 접근성 > 디스플레이), iOS 는 접근성 > 동작, Android 9 이상은 접근성 > 애니메이션 삭제. 2020-01 부터 주요 브라우저 지원(Baseline 널리 쓰임)
  - 출처: https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion
  - 뜻: 이 PC(Windows 11)에서 애니메이션 효과를 끄면 바로 확인할 수 있다

### 5-5. 그림과 UI 를 한 결로 맞춘 디자인 시스템

- **확인함 (GitLab Pajamas 브랜드 일러스트)**: 선이 그림의 바탕이고, 한 그림 안에서는 한 가지 선 굵기만. 디지털은 2px, 큰 인쇄물은 15px. 한쪽만 둥근 모서리는 정사각형 폭의 25~30%, 네 모서리가 다 둥글면 5~10%. 색은 뜻을 전할 때만. UI 아이콘을 그림 안에 넣고, 선은 코드 줄에서 왔으며, 마케팅 그림은 자체 아이콘 체계의 연장이다
  - 출처: https://design.gitlab.com/brand-design/visual-design-brand-illustrations
- **확인함 (Duolingo, 2-7 참고)**: 2018 개편에서 UI 의 둥근 버튼이 일러스트의 둥근 도형 언어를 따라갔다
- **확인 전**: Polaris 일러스트 1.5px 선, 4px 모서리(서드파티 스킬 모음에서만 봄). Polaris 공식 아이콘 페이지의 모서리 1~3px 는 아이콘 규칙이라 일러스트와 다르다
- **우리에게**: 캐릭터의 선 굵기 = 패널 테두리와 아이콘 선 굵기, 캐릭터 모서리 비율 = 카드 모서리 비율로 묶는 방식(3-5 화풍 규칙)의 실제 사례가 GitLab 이다

## 6. AI 가 만든 화면의 흔한 꼴

### 6-1. 정리된 목록

- **확인함 (impeccable, Paul Bakaus, "The visible tells of AI design")**: 68개 패턴(탐지 규칙 62 + 디자인 리뷰 6)이라고 적는다. 날짜 표시는 없다. 이 조사와 맞닿는 것만 고르면
  - 레이아웃: 큰 숫자와 작은 라벨의 히어로 지표(설명 없이 숫자를 앞세우지 말 것), 똑같은 아이콘-제목-글 카드 격자, 카드 속 카드(간격, 글꼴, 구분선으로 평평하게), 모든 간격이 같아 묶음이 안 보임
  - 시각: 장식용 격자 선 바탕, 둥근 요소의 두꺼운 색 테두리, 카드 옆 굵은 띠, 가는 테두리와 넓은 그림자를 함께, 카드 크기와 상관없이 큰 모서리, 어디나 유리 효과와 빛
  - 색: 보라 그라데이션과 어두운 바탕의 밝은 청록, 글자 그라데이션, 빛나는 강조색의 어두운 모드, 색 바탕 위 회색 글자, 습관적인 크림색과 베이지
  - 글꼴: Inter, Geist 같은 기본 글꼴, 제목 위 작은 라벨과 알약 배지, 아이콘 타일 위에 제목
  - 모션: 바뀌는 게 없는데 깜빡이는 점, 장식용 커서, 튀는 탄성 곡선
  - 그림: 자리 표시처럼 보이는 원과 블록 그림, 거칠게 그린 SVG 그림
  - 출처: https://www.impeccable.style/slop
- **확인함 (Anthropic frontend-design 스킬, GitHub, 마지막 커밋 2026-09-03)**
  - 큰 숫자, 작은 라벨, 보조 지표, 그라데이션 강조는 기본값이니 정말 최선일 때만
  - 생성된 페이지의 흔한 글꼴 꼴: 제목의 한 단어만 기울이거나 색 바꾸기, 라벨 전부 대문자, 내용 위 불필요한 라벨. 번호 표시(01/02/03)는 실제로 순서가 있을 때만
  - 사용자가 일으키지 않은 움직임은 아껴 쓰고, 구역마다 나타나며 올라오는 효과와 모든 카드의 호버 효과는 AI 생성으로 읽힌다. 사람의 동작에 답하는 움직임(열기, 펼치기, 확인)은 무엇이 바뀌었는지 보여 줄 때 좋다
  - 지금 AI 디자인이 모이는 꼴 다섯: (1) 따뜻한 크림 바탕 + 대비 큰 세리프 + 테라코타 강조, (2) 거의 검정 바탕 + 형광 초록이나 주홍 강조 하나, (3) 가는 선과 모서리 0 의 신문 레이아웃, (4) 똑같은 둥근 카드, 하나뿐인 모서리 값, 같은 흐린 회색 그림자, 장식용 그라데이션, (5) 주제와 상관없는 틀(제목마다 자간 넓힌 대문자 라벨, 가운뎃점으로 이은 메타 문자열, 색을 살짝 섞은 거의 검정, 작은 데이터 라벨의 고정폭 글꼴, 링크 끝 화살표)
  - 출처: https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md
- **확인 전**: Tailwind 기본 `bg-indigo-500` 이 보라 기본값의 뿌리라는 설명. Adam Wathan 의 X 글은 2차 글(prg.sh)이 링크한 것만 봤고, 원문은 열지 않았다. 그 기본값이 LLM 출력으로 이어진다는 인과는 글쓴이의 해석이다
  - 출처: https://prg.sh/ramblings/Why-Your-AI-Keeps-Building-the-Same-Purple-Gradient-Website

### 6-2. 우리 기준과 부딪히는 곳 (판단 필요)

- `docs/design-judge.md` 의 "바탕은 색이 살짝 섞인 검정과 흰색"은 Anthropic 스킬이 흔한 꼴 (5)로 꼽는 "색을 살짝 섞은 거의 검정"과 겹친다. 크림 바탕(1)도 "색 섞인 흰색"의 흔한 결과다. 원칙을 버리기보다, 섞는 색을 컨셉의 사물(종이, 연습장, 형광펜 색)에서 끌어오는지로 판정하는 게 맞는지 3-3 에서 정한다
- 코드 도구라 고정폭 글꼴은 에디터에 꼭 필요하다. 다만 작은 라벨까지 고정폭으로 쓰면 흔한 꼴 (5)가 된다. 고정폭은 코드에만

### 6-3. 처방 (구체적 참고물과 제약)

위 두 자료와 이 조사의 사물에서 나온 것:

1. 형용사가 아니라 사물로 시작: 오답노트 한 장, 링 단어장, 10분 타임테이블, 빨간 펜 동그라미(1절)
2. 숫자는 설명과 함께만. 혼자 푼 비율은 칠한 칸, 동그라미 개수 같은 흔적으로 보이고 숫자는 눌러야 나온다
3. 모서리 값을 위계별로 둘 이상(종이 한 장과 그 안의 칸이 다르게). 그림자 대신 종이 겹침과 선
4. 색은 뜻에만: 동그라미의 빨간 펜, 형광펜, 코테/CS 두 색. 그라데이션 없음
5. 움직임은 사람의 동작에 답할 때만(카드 넘기기, 동그라미 그리기, 형광펜 긋기). 페이지 들어올 때 연출 없음. 탄성 곡선 없음
6. 대문자 라벨, 가운뎃점 메타, 링크 끝 화살표, 의미 없는 번호를 쓰지 않는다(한국어 화면이라 대문자 라벨은 영어 섞을 때 주의)

## 7. 컨셉 재료

결정이 아니라 3-2 심사에 넣을 재료다. 각각 중심 사물, 성격 한 줄, 뜻 있는 움직임 한 줄.

1. **빨간 펜 채점**
   - 사물: 시험지와 빨간 펜 동그라미, 세모
   - 성격: 내 풀이를 내가 채점하는 담담한 선생님
   - 움직임: "혼자 풂"을 고르면 펜이 한 획으로 동그라미를 그린다(약 300ms, 감속)
2. **링 단어장**
   - 사물: 고리에 꿴 플래시카드 묶음
   - 성격: 주머니에 넣고 다니는 작은 습관
   - 움직임: 카드를 넘기면 고리를 따라 뒤로 돌아가고, 오늘 몫을 다 넘기면 고리가 딸깍 닫힌다
3. **오답노트 한 장**
   - 사물: 칸이 나뉜 노트 한 장과 풀이를 가린 포스트잇
   - 성격: 막힌 이유를 솔직하게 적어 두는 기록장
   - 움직임: 복습 때 포스트잇을 떼어 접근과 막힌 곳이 드러난다
4. **10분 칸 플래너**
   - 사물: 한 칸이 10분인 타임테이블과 두 색 형광펜
   - 성격: 빈 칸을 세지 않고 칠한 칸만 보는 플래너
   - 움직임: 기록을 저장하면 그 시간 칸이 왼쪽부터 칠해진다. 비어 있는 칸은 그대로 종이
5. **연습장 여백**
   - 사물: 모눈 연습장과 시험지 여백의 손풀이
   - 성격: 정리 전의 생각을 허락하는 자리
   - 움직임: 접근 칸에 쓴 두 줄이 "맞았습니다" 뒤 정리된 요약 한 줄로 옮겨 적힌다
6. **인덱스 탭 개념서**
   - 사물: 옆면에 단원 탭을 붙인 두꺼운 개념서
   - 성격: 코테와 CS 를 한 권에 묶은 내 책
   - 움직임: 탭을 누르면 그 단원 쪽으로 책장이 넘어간다(좁은 패널에서 메모 네 칸 전환)
7. **초시계 랩**
   - 사물: 기계식 초시계와 랩 기록
   - 성격: 오늘 몇 분 있는지 묻고 그만큼만 재 주는 코치
   - 움직임: 5분/30분/1시간을 고르면 바늘이 그 눈금까지 돌아가 선다. 막힌 곳을 적으면 랩이 찍힌다
8. **새 장 (책갈피)**
   - 사물: 책갈피와 새로 넘긴 페이지
   - 성격: 쉬다 돌아와도 따지지 않고 새 장을 펴 주는 책
   - 움직임: 월요일이나 오래 쉰 뒤 처음 열면 책갈피가 새 쪽으로 옮겨 꽂힌다(새 출발 효과, 연속 기록 대신)
